# Ryzer OS 3.4: Ryzer Sync

Date: 2026-10-30 · Status: design approved in conversation, pending written-spec review

## Why

The owner wants a big feature that other frontends don't have. With Ryzer Sync, someone with several devices (RG DS,
AYN Thor, a phone) can stop a game on one and continue on another. Their saves, play history and library extras
follow them.

It works over the local Wi-Fi only, with no account and no cloud server.

## Success criteria

1. **Pairing:**
   - *Settings → Ryzer Sync → Pair a device* shows a 6-digit code on one device. You enter it on the other device,
     which found the first on the network.
   - Each side stores a shared 256-bit secret. Pairing works once, and either side can unpair.
2. **Discovery:** paired devices on the same network find each other within 10 s. The Sync screen lists them with
   last-seen time.
3. **What syncs:**
   - Play times, sessions, last-played times, favorites, ratings, statuses, notes, collections and pins.
   - User themes and the avatar.
   - Emulator save files for games both devices have (matched by system + file name, then size).
4. **When it syncs:**
   - When a play session ends, that game's saves and the play state are pushed to reachable paired devices.
   - On Ryzer start, and every 10 min on Wi-Fi, a full catch-up runs.
5. **Continue here:** if another device played a game more recently than this one, Home shows "Continue *Game*
   (played on *Thor* 12 min ago)". Choosing it syncs that game's saves first, then launches.
6. **Never loses a save:**
   - Before any file is replaced, the old one is copied to `RyzerOS/sync-backups/<date>/<path>`. The 20 newest per
     game are kept.
   - *Sync → History* lists every replaced file, with one-tap restore.
7. **Settings:** off by default. *Sync saves* can be turned off separately, which syncs stats and library only.
8. **Safety:** no sync while a game is running on either device for that game. A file that is still being written
   (size changing over 2 s) waits.

## Design

### Units

| Unit | Purpose |
|---|---|
| `SyncMerge` (pure, unit-tested) | Merge rules for `state.json` sections. |
| `SavePaths` (pure where possible) | Per-emulator save locations and file patterns, mapped to a game. |
| `SyncPlan` (pure, unit-tested) | Given two file manifests, decide push / pull / conflict-keep-newer with a backup. |
| `SyncNet` | UDP discovery, a small HTTP server and client, HMAC-SHA256 request signing. |
| `SyncService` | Scheduling, running plans, writing backups. |
| `SyncScreens` | Pairing, device list, history and restore. |

### SyncMerge

| Data | Merge rule |
|---|---|
| Per-game time | Recomputed from the union of sessions, deduped by (device, start). |
| Sessions | Union. |
| Last played | Max. |
| Favorites / pins | Union, with deletions recorded as timestamped tombstones; the later event wins. |
| Ratings / status / notes | The later write wins (per-field timestamps). |
| Collections | Union of members, with tombstones. |

### SavePaths

The first set covers:

| Emulator | Save location and files |
|---|---|
| RetroArch | `RetroArch/saves/**/<rom stem>.srm` (+ `states/**/<stem>.state*`) |
| PPSSPP | `PSP/SAVEDATA/<game id>*`, game id read from the ISO's `PARAM.SFO`. Name match falls back to "all of SAVEDATA" with a warning. |
| DuckStation | `duckstation/memcards/<stem>_*.mcd` |
| DraStic | `DraStic/backup/<stem>.dsv` |
| melonDS | `<rom dir>/<stem>.sav` |
| mGBA, Pizza Boy, My Boy! | `<rom dir>/<stem>.sav` (+ app folders) |
| Azahar, Citra | `<emu>/sdmc/Nintendo 3DS/<id0>/<id1>/title/<tid>/data`, title id read from the ROM header |
| Dolphin | `dolphin-emu/GC/<region>/Card A` (whole-card sync, flagged as such) |
| NetherSX2, AetherSX2 | `memcards/Mcd001.ps2` (whole-card) |

Emulators not listed don't sync saves, and Ryzer says so on the game's Sync info.

### Network

- **Discovery:** UDP broadcast on port 47821, carrying `{device id, name, version, http port}`.
- **HTTP:** a small `ServerSocket`-based server on port 47822.
  - Every request carries `X-Ryzer-Device`, `X-Ryzer-Time` and an HMAC of method+path+time+body-hash. Requests more
    than 60 s old are rejected.
  - Files stream in 64 KB chunks with a SHA-256 check.
- **Scope:** LAN only. Requests from non-private addresses are refused.

### Manifests and conflicts

- A file entry is `{path key, size, mtime, sha256}`.
- The newer mtime wins. If both sides changed since the last sync (tracked per file), the newer one still wins, the
  other is backed up, and a "conflict kept newer" item goes in History with a Ryzer notice.

## Testing

- **Unit:**
  - `SyncMerge` with tombstones and clock skew.
  - `SyncPlan` cases: push, pull, equal, both-changed, missing-on-one-side, file-being-written.
  - HMAC signing and replay rejection.
  - `SavePaths` matching on fixture trees.
- **Emulator:** two emulator instances in one CI job, on the same virtual network (two AVDs, adb ports 5554/5556).
  1. Pair them.
  2. Write a fake RetroArch `.srm` on A.
  3. Run a sync and check that B has it.
  4. Check that B's old copy is in sync-backups.
  5. Check that "Continue here" appears on B.
  Plus the stress test with Sync on.
- **Manual:** the owner tries two real devices before the release is marked as more than "beta".

## Out of scope

Internet or cloud sync, syncing ROMs themselves, syncing emulator settings, the Linux edition (later, same protocol).
