# Ryzer OS 3.3: RetroAchievements

Date: 2026-10-30 · Status: design approved in conversation, pending written-spec review

## Why

The owner wants a big feature that frontends like Cocoon and iiSU don't have. Ryzer will show RetroAchievements (RA)
progress for every game it can identify, and track it live on the second screen while you play.

Achievements are still earned inside the emulators: RetroArch, DuckStation, PPSSPP, Dolphin, PCSX2-based apps and
others that support RA, signed in there. Ryzer only reads progress through the public RA Web API. It never unlocks or
submits anything.

## Success criteria

1. *Settings → RetroAchievements*:
   - Fields for username and Web API key (from retroachievements.org → Settings → Keys).
   - A *Test sign-in* action that shows the account's points and rank.
   - *Sign out*.
   - The key is stored only in Ryzer's config, and is never logged or shown again in full.
2. **Matching:**
   - Cartridge systems are matched by RA's own hash: nes, snes, gb, gbc, gba, n64, genesis, mastersystem, gamegear,
     pce, atari2600, ngpc and nds.
   - Disc systems (psx, ps2, psp, saturn, segacd, dreamcast, gc) are matched by normalised title against RA's game
     list. A name match is shown as "matched by name".
3. **Game list (Blades and Classic):**
   - A trophy badge with `earned/total` for matched games.
   - The details pane shows a 16-segment progress meter, plus "Mastered" when hardcore is complete.
4. **Achievements screen** (game options → *Achievements*, or Y in the details pane):
   - Every achievement with its badge, title, description, points and true ratio.
   - Locked badges are greyed out.
   - Sorting: unlocked first, then by rarity.
5. **Top screen**, when a matched game is selected: the three most recent unlocks and the rarest unlocked one.
6. **Now Playing:**
   - An *Achievements* page with a counter, a progress meter and the next locked achievements.
   - It refreshes every 30 s while the game runs, only on Wi-Fi or Ethernet.
   - A new unlock shows a banner with the badge, and plays the "fav" sound.
7. **Profile:** total points, rank, recently played RA games, and "Mastered" count.
8. **Offline:**
   - Everything shows the last fetched data, with an "updated 2 h ago" line.
   - No network means no errors in the UI, only a quiet "offline" chip.

## Design

### Units

| Unit | Purpose |
|---|---|
| `RaHash` (pure Kotlin, unit-tested) | Hash a ROM the way RA does, per system. |
| `RaClient` | HTTP GET against `https://retroachievements.org/API/`, JSON parsing, a 1 request/s rate limit, and a disk cache. |
| `RaStore` | Per-game cache in `RyzerOS/ra/<gameId>.json` plus badge images in `RyzerOS/ra/badges/`; mapping of ROM key to RA game id in `RyzerOS/ra/ids.json`. |
| `RaScreens` | The Achievements screen, the Settings menu and the Now Playing page. |

### RaHash

These rules follow RA's published `rc_hash` behaviour:

| System | Hash |
|---|---|
| nes | MD5 of the file without its 16-byte iNES header (when it starts with `NES\x1a`) |
| snes | MD5 without the 512-byte copier header (when `size % 1024 == 512`) |
| n64 | MD5 after converting byte order to big-endian (.z64) from .v64 (byte-swapped) or .n64 (little-endian) |
| atari7800/lynx | header stripped (not in scope; systems not in Ryzer) |
| all other cartridge systems | plain MD5 of the file |
| zip files | not hashed (RA hashes the inner file); they fall back to name match |

### API endpoints

- `API_GetGameList.php?i=<consoleId>&h=1&f=1`: hash → game id. Cached per console for 7 days.
- `API_GetGameInfoAndUserProgress.php?g=<id>&u=<user>`: achievements and the user's unlocks.
- `API_GetUserSummary.php` / `API_GetUserProfile.php`: profile and recent games.
- Badge images: `https://media.retroachievements.org/Badge/<BadgeName>.png` (and `_lock.png`).

### Console ids

Mapped in `systems.json` as a new optional `ra` field (for example nes=7, snes=3, gba=5, psx=12, psp=41, …).

### Background work

- On rescan, Ryzer hashes un-matched cartridge ROMs on the existing worker thread. Hashing is limited to files of
  64 MB or less, and stops while a game runs.
- Results are cached by file size + mtime, so a library is hashed once.

## Testing

- **Unit:**
  - `RaHash` on fixtures: an iNES file with and without its header, an SNES file with a 512-byte header, an N64 file in
    all three byte orders.
  - JSON parsing of recorded API responses (fixtures in `src/test/resources`).
  - Title normalisation for name matching.
- **Emulator:** the Settings screen and the Achievements screen populated from a fixture cache (no live account in CI).
  Plus a shot of the Now Playing achievements page, the stress test, and the crash, perf and swap gates.
- **Live check:** an optional CI step, if an `RA_USER` / `RA_KEY` secret is present, runs *Test sign-in* against the
  real API.

## Out of scope

Unlocking achievements in Ryzer itself, hardcore-mode enforcement, leaderboards, the Linux edition.
